한 말풍선 안에서 의미 계층을 유지

Action은 작은 이탤릭 보조 문장, Dialogue는 기본 본문으로 표시한다. 개발자용 ACTION 라벨은 채팅 기록에서 노출하지 않는다.

  • 말풍선과 timestamp는 user turn당 하나다.
  • Action이 먼저, Dialogue가 다음인 순서를 시각적으로 보존한다.
  • 성공 enqueue 뒤 pending Action과 Dialogue draft를 함께 비운다.

Proposed · Validation

잘못된 Action은 pending으로 확정하지 않음

300자를 초과하면 counter와 field를 error로 표시하고 `완료`를 비활성화한다. Dialogue draft는 그대로 유지한다.

  • Action을 자동 truncate하지 않는다.
  • 검증 오류 중에는 전체 turn 전송도 막는다.

구현 계약

  • Action editor의 `완료`는 pending 상태 전환이며 provider 전송·Conversation 저장을 발생시키지 않는다.
  • pending Action과 Dialogue는 한 user turn의 ordered segments로 함께 전송·저장한다.
  • pending Action이 있는 상태에서 Action 버튼 또는 연필 버튼을 누르면 기존 내용이 채워진 editor를 연다. 두 번째 Action을 추가하지 않으며, `취소`는 기존 pending Action을 유지하고 `완료`는 이를 교체한다. Dialogue draft는 두 경우 모두 보존한다.
  • Action-only는 pending Action이 있고 Dialogue가 비어 있을 때 사용자가 전송 버튼을 직접 누른 경우에만 허용한다.
  • enqueue가 거부되거나 실패하면 pending Action과 Dialogue draft를 모두 보존한다.
  • 화면 표시만 합치고 persistence에서 독립 turn 두 개로 저장하는 구현은 이 Visual Spec을 충족하지 않는다.
  • 캐릭터의 구조화된 Action + Dialogue도 같은 말풍선 안에서 Action, 구분선, Dialogue 순서로 표시한다. role별 정렬과 말풍선 색상만 다르게 유지한다.
  • 사용자와 캐릭터 모두 두 segment가 함께 있을 때만 구분선을 표시하며, Markdown 강조나 임의 delimiter 문자열로 segment 타입을 추론하지 않는다.
  • Dialogue-only, 첨부 버튼, Action 300자 제한은 기존 동작을 유지한다.
화면의 메시지 예시는 실제 대화가 아닌 UI 검토용 합성 텍스트다.
