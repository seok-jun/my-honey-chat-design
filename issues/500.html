Persona별 대화 목록이 홈이 된다

Persona가 2명 이상이면 앱을 열었을 때 대화 목록이 먼저 보이고, 행을 누르면 그 Persona의 채팅방으로 들어간다. 1명이면 목록을 거치지 않는다.

설계 초안 · 앱 구현 전

이 시안은 화면 배치, 정보 계층, UI 상태의 구현 기준이다. 저장·전환·provider 동작은 실행하지 않는다. 모든 이름과 문장은 합성 예시이며 실제 대화 내용을 담지 않는다. 색·글자·간격 값은 foundation/tokens.json을 따른다.

테마 · foundation은 다크를 기본으로 하고 라이트는 시스템 설정을 따를 때 쓴다.

행 구성 기준

왼쪽

아바타 size.avatarList 52. 온라인 점 size.onlineDot 10, 색은 star. 접속 상태 데이터가 없으므로 항상 켬이다.

가운데

이름 16sp SemiBold. 아래 마지막 메시지 한 줄 13sp onSurfaceVariant, 한 줄을 넘으면 말줄임. 내가 보낸 메시지면 앞에 나: 를 붙인다.

오른쪽

마지막 메시지 시각 typography.scale.meta 11sp onSurfaceVariant. 오늘은 시각, 어제는 어제, 그 이전은 날짜.

정렬과 터치

마지막 메시지 시각 역순. 행 높이는 size.minTouchTarget 48 이상(아바타 52 기준 76). 행 전체가 채팅방 진입 대상이다.

목록이 1행뿐이면 매 실행마다 탭이 한 번 늘어난다. 앱 시작 시 바로 채팅방을 연다. 목록은 Persona가 2명 이상이 되면 나타난다.

진입 분기

  • Persona 1명 → 채팅방. 뒤로가기는 기존과 같다.
  • Persona 2명 이상 → 대화 목록 홈. 행 선택 시 채팅방.
  • 채팅방에서 뒤로가기 → 대화 목록(2명 이상일 때만).
  • 설정에서 들어가는 Persona 관리 목록(#437)과 전환 시트는 그대로 남는다.

표현 기준

  • 메시지가 없으면 안내 문구 한 줄을 넣고 시각은 비운다. 정렬에서는 가장 아래로 둔다.
  • 마지막 메시지에 글이 없고 미디어만 있으면 종류 이름(사진, 음성, 동영상)을 넣는다.
  • 미디어 종류 이름에도 보낸 쪽 접두사 규칙을 그대로 적용한다.
  • 마지막 메시지가 행동 묘사(message_kind = action)면 본문 대신 그 묘사를 한 줄로 쓴다. 라벨을 따로 붙이지 않는다.

다시 시도

문구와 복구 동작은 #437의 관리 목록 실패 상태와 같은 기준을 쓴다. 실패해도 대화 상대는 바뀌지 않는다.

구현 기준 요약

  • 안 읽은 수 배지는 넣지 않는다. message 테이블에 읽음 상태 컬럼이 없어 schema 변경이 필요하다.
  • 선톡 칩과 선톡 대화의 상단 고정은 이 이슈 범위가 아니다.
  • 온라인 점은 항상 켬이다. 최근 대화량으로 구분하는 방안은 seok-jun/my-honey-chat#501에 기록했다.
  • 캐릭터 말풍선과 카드에는 outline 1dp 테두리를 준다. surface와 background의 대비가 1.1~1.2:1이다.
  • 본문 글자 크기를 20sp로 올려도 행이 깨지지 않아야 한다. 이름과 미리보기는 각각 한 줄을 유지하고 넘치면 말줄임으로 자른다.
  • 기존 Persona 관리 목록과 전환 시트의 동작은 바꾸지 않는다.
