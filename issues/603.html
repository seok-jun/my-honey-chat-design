구현 기준

  • 사진 카드의 기존 순서와 프로필 사진 영역은 유지한다. FACE/BODY는 각각 독립적으로 편집한다. ‘내용 수정’은 카드 안 입력란을 열며 화면·모달 이동을 추가하지 않는다.
  • 저장은 입력이 1~300자이고 공백뿐이지 않을 때 가능하다. 원문을 조용히 잘라 저장하지 않는다. 취소·뒤로 가기는 미저장 입력을 반영하지 않는다.
  • 저장 중에는 해당 편집의 저장·취소와 사진 변경을 비활성화한다. 실패는 입력 아래에서 알리고 입력을 유지한다. 사진 세대가 바뀌면 오래된 입력을 저장하지 않고 최신 상태를 다시 불러오도록 안내한다.
  • 사진 없음·분석 미완료/실패·분석 중에는 상태 안내와 편집 비활성을 표시한다. 사진 선택·삭제·다시 분석은 기존 정책을 따른다. 미완료 상태의 전체 문구 개편은 범위 밖이다.
  • 화풍 선택은 2D·실사풍·UNKNOWN 세 값이다. 저장한 화풍은 이후 생성에 적용한다. 자동 관찰과 수동 보정을 내부에서 구분하며 원본 결합과 imported 제한을 유지한다. 기존 생성 요청의 snapshot은 유지하며 저장 이후 시작한 요청에만 반영한다.
  • 최소 터치 영역 48px, 입력 label·오류 연결과 상태 live 안내를 제공한다. 색·타이포그래피·라이트 테마는 foundation 기준을 따른다.

이 HTML의 상태 전환·저장 표시는 배치 확인용이다. 네트워크·DB·모델 호출은 없으며 디자인 게시가 제품 구현 완료를 뜻하지 않는다. 기능 정책은 앱 Issue 본문을 따른다.
