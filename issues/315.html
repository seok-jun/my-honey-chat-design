[Media][Lifecycle] Persona-scoped 사용자 미디어 자산·Chat 참조 분리·갤러리 보존

대상 화면: 「미디어 모아보기」, 전체 화면 미디어 뷰어, 미디어 삭제 확인 dialog, 채팅 message bubble의 media 자리. 미디어는 Persona가 소유한 자산이고 message는 그 자산을 참조한다. 사용자가 미디어를 직접 지워도 대화는 남고, 그 자리에 「삭제된 미디어」가 보인다. 이 HTML은 화면 배치, 정보 계층, UI 상태와 인터랙션의 구현 기준이다.

이 문서가 정하는 것
삭제 진입 위치, 영향 고지 dialog, 삭제 뒤 화면, 갤러리 타일과 bubble의 DELETED·MISSING 표현, 문구.

정하지 않는 것
catalog 저장, 가용성 판정, 파일 삭제 journal, 갤러리 source 전환. SDD persona-media-assets의 D-006·D-009·D-010·D-011과 MEDIA-03이 소유한다.

  • Top bar, 2열 격자(GridCells.Adaptive(132.dp), 간격 6dp, 여백 8dp), 정사각 타일, 정렬(최신순)은 Current와 같다.

  • MISSING 타일은 열기와 저장이 없다. 타일 본문은 눌러도 반응하지 않는다. 저장 버튼 자리(오른쪽 아래)에 삭제 아이콘(DeleteOutline, contentDescription 「미디어 삭제」제안 문구)을 둔다. 누르면 3번 삭제 확인으로 간다.
  • DELETED 항목은 목록에 없다. 모든 항목이 사라지면 기존 빈 상태 「아직 모아볼 이미지나 영상이 없어.」를 그대로 쓴다.
삭제 진입은 두 곳뿐이다 AVAILABLE은 뷰어 하단(2번), MISSING은 타일의 삭제 아이콘. 길게 누르기 같은 숨은 제스처는 만들지 않는다.
연결되지 않은 항목은 삭제 진입이 없다 mediaId == null(key가 legacy:)인 항목은 AVAILABLE이면 Current 타일 그대로, MISSING이면 누락 표시만 하고 삭제 아이콘을 그리지 않는다. backfill 뒤 asset이 되면 삭제할 수 있다.

삭제는 저장 옆, 한 단계 약하게

  • 검은 전체 화면, 오른쪽 위 ✕ 닫기, 미디어 영역(위아래 64dp 여백)은 Current와 같다.
  • 하단 가운데 한 줄에 [삭제] [갤러리에 저장]을 12dp 간격으로 둔다. 기존 「갤러리에 저장」 OutlinedButton은 오른쪽에 그대로 남는다.
  • 「삭제」제안 문구는 error 색 TextButton + DeleteOutline 아이콘이다. 누르면 뷰어 위에 3번 dialog가 뜬다.
  • 이미지와 영상 모두 같다. 영상은 재생 중이어도 버튼 위치가 같다.
  • 「저장 중」(기존 진행 표시) 동안에는 삭제 버튼을 비활성화한다(투명도 38%).
대화에서 연 뷰어에는 삭제가 없다 message bubble을 눌러 연 뷰어는 Current와 같다(저장만). 삭제는 모아보기 항목에서만 한다(D-010). 모아보기에서 열었더라도 mediaId == null이면 삭제 버튼을 그리지 않는다.

이 미디어를 삭제할까?

이 미디어가 대화에 남아 있으면 그 자리는 「삭제된 미디어」로 표시돼. 대화 내용은 지워지지 않아.

삭제하면 되돌릴 수 없어.

취소삭제

영향을 먼저 말하고 한 번 묻는다

  • Material3 AlertDialog. 제목 → 영향 고지 → error 색 경고 → [취소] [삭제] 순서다.
  • 영향 고지는 세 가지다: 대화 자리는 「삭제된 미디어」로 남고 대화 내용은 지워지지 않는다 / 되돌릴 수 없다 / 필요하면 먼저 저장한다(D-010).
  • MISSING 항목은 저장할 파일이 없으므로 「필요하면 먼저 「갤러리에 저장」해줘.」 줄을 뺀다.
  • 참조하는 message 개수는 보여주지 않는다. 0개일 수도 있어서 “남아 있으면”으로 말한다.
  • 취소, 바깥 영역 탭, 뒤로 가기: dialog만 닫힌다. 뷰어나 모아보기는 그대로이고 서비스는 호출하지 않는다.
  • 삭제: 한 번만 호출한다. 결과가 올 때까지 두 버튼을 비활성화하고 dialog를 닫지 않는다. 결과는 4번 상태로 간다.
확인 버튼은 결과를 그대로 말한다 「삭제」는 error 색 filled 버튼이다. 기본 초점은 두지 않는다. 이 dialog 안에 저장 버튼 같은 다른 action을 넣지 않는다.
문구 제목 「이 미디어를 삭제할까?」, 고지 두 줄, 경고 「삭제하면 되돌릴 수 없어.」, 버튼 「취소」·「삭제」 모두 제안 문구. 「삭제된 미디어」와 「갤러리에 저장」은 PLAN·기존 문구다. 톤은 기존 미디어 문구(반말)에 맞춘다.

지워지면 바로 사라지고, 실패하면 그대로다

  • DELETED 결과: dialog와 뷰어를 닫고 모아보기로 돌아온다. 항목은 목록에서 빠진다. snackbar 「미디어를 삭제했어.」제안 문구.
  • ALREADY_DELETED, NOT_FOUND: 사용자가 원한 결과와 같으므로 성공과 똑같이 닫는다. 오류를 보여주지 않는다.
  • BLOCKED: dialog만 닫고 뷰어(또는 모아보기)는 그대로 둔다. snackbar 「지금은 미디어를 삭제할 수 없어. 잠시 뒤에 다시 해줘.」제안 문구.
  • 예외: BLOCKED와 같은 화면. snackbar 「미디어를 삭제하지 못했어.」제안 문구 (기존 「프로필 사진을 삭제하지 못했어.」와 같은 형식).
  • MISSING 타일에서 시작했다면 뷰어가 없으므로 모아보기에 그대로 머문다.
snackbar는 모아보기 화면 위에 보인다 뷰어·모아보기가 떠 있는 동안에도 결과 snackbar가 화면 아래에 보여야 한다. 채팅으로 돌아간 뒤에야 보이면 안 된다.
파일 삭제가 늦어도 화면은 DELETED다 tombstone이 커밋되면 성공으로 표시한다. 파일 제거 재시도(pending)는 화면에 올리지 않는다(02-to-be §4).

  • 이미지·영상: 종류와 상관없이 220×120dp 고정 상자. 모서리 12dp, 점선 테두리(흰색 22%), 배경 검정 22%. 가운데에 아이콘과 문구(12sp, muted).

  • 본문이 있으면 placeholder와 본문 사이 간격 8dp는 지금과 같다.

근거가 없으면 흔적을 만들지 않는다

  • 연결 없음 + media 없음: 복원·병합으로 들어온 「[사진]」 row처럼 media 연결도 descriptor도 없는 row는 지금처럼 본문만 보인다. placeholder를 추측해서 만들지 않는다(D-011).
  • AVAILABLE: 이미지·영상·음성 bubble은 Current와 같다.
  • 연결되지 않은 descriptor(backfill 전 등): 지금처럼 descriptor로 그린다. 파일이 없으면 기존 「이미지 파일을 열 수 없어.」 문구 또는 빈 영상 상자가 그대로 나온다(02-to-be §3.4).
  • 대화에서 연 뷰어: 저장만 있다. 삭제 버튼을 그리지 않는다.
시간 옆 설명은 문서용이다 왼쪽 phone의 “· 연결 없음” 같은 설명은 이 Visual Spec의 주석이다. 앱에 표시하지 않는다.

범위 밖 — 이 Visual Spec이 바꾸지 않는 것

  • 갤러리 source를 catalog와 연결되지 않은 descriptor의 합집합으로 바꾸는 것(D-009, MEDIA-03). 화면이 그대로라 Visual Spec 변경이 없다.
  • rollback 메뉴와 「스냅샷 복원」 진입 재개방(D-013, MEDIA-05). 기존 위치의 기존 진입이라 Visual Spec 변경이 없다. 모양은 #106·#338 Visual Spec을 따른다.
  • 음성(AUDIO)을 갤러리에 보이기, 새 내보내기 UX, Persona 삭제 UI, 노출 기간 유실 media 복구 결과 안내. 이 Issue에서 새 화면을 만들지 않는다.
  • 연결되지 않은 descriptor의 파일 누락 표현 통일. 이번 범위는 연결된 asset의 DELETED·MISSING만이다.
상태 흐름: 모아보기 → (AVAILABLE 타일 → 뷰어 → 삭제) 또는 (MISSING 타일 → 삭제 아이콘) → 삭제 확인 → (취소 → 원래 화면) 또는 (삭제 → 성공이면 모아보기에서 항목 제거 + snackbar, BLOCKED·예외면 원래 화면 + snackbar). 이후 그 media를 참조하던 message는 대화에서 「삭제된 미디어」 placeholder로 보인다.
모든 이미지·영상·대화 본문은 합성 자리 표시다. 실제 사용자 대화나 미디어를 쓰지 않았다.
