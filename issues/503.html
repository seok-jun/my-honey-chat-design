some:You · Issue #503 · 입력창

떠 있는 알약 입력창과 전송 버튼의 두 상태

입력칸과 전송 버튼을 surfaceVariant 알약 컨테이너에 담는다. 입력이 비어 있으면 전송은 회색 아이콘, 글자가 있으면 primary 원형 48이 된다.

설계 초안 · 앱 구현 전

이 시안은 화면 배치, 정보 계층, UI 상태의 구현 기준이다. 전송·첨부·생성 동작은 실행하지 않는다. 모든 문장은 합성 예시이며 실제 대화 내용을 담지 않는다. 색·글자·간격 값은 foundation/tokens.json을 따른다.

foundation과 다르게 가는 한 가지. foundation 5절은 입력창을 "왼쪽 ＋ 버튼(사진), 오른쪽 전송"으로 적지만, 앱에는 보조 버튼이 ＋ 첨부 / ✧ 행동 / ▧ 생성 세 개이고 그 배치는 #213과 #465가 확정했다. 보조 버튼 줄을 입력칸 위에 그대로 유지하고 알약 안에는 입력칸과 전송 버튼만 둔다. 세 버튼을 ＋ 하나로 합치는 변경은 그 두 이슈의 시안 갱신이 선행이므로 이 이슈에서 하지 않는다. foundation에는 "보조 버튼 줄" 패턴을 추가하자고 별도로 제안한다.

바꾸는 것 / 두는 것

바꾼다

입력 영역을 떠 있는 알약 컨테이너로. 최소 높이 48, 모서리 24, 최대 5줄. 전송 버튼의 상태별 색·모양. 첨부 미리보기 모서리 16.

두다

보조 버튼 줄의 구성·순서·목적지, 행동 묘사 editor와 pending 표현, 첨부 가능 종류, 전송 조건과 글자 수 제한, 비활성 조건.

알약 바로 위, 왼쪽 정렬. 각 버튼의 터치 영역 size.minTouchTarget 48. 글자 13sp onSurfaceVariant. 구성과 순서는 #465 기준.

전송이 primary 원형 48로 커진다. 비활성 → 활성 전환 모션은 seok-jun/my-honey-chat#505에서 다룬다.

판정

  • 활성 조건은 기존과 같다. 공백만 입력한 경우는 활성으로 보지 않는다.
  • 첨부한 사진만 있고 글자가 없을 때의 활성 여부는 기존 전송 조건을 그대로 따른다. 이 시안은 그 조건을 바꾸지 않는다.
  • 활성·비활성 모두 화면 낭독기용 이름을 제공하고, 비활성일 때는 비활성 상태를 알린다.

기준

  • 대기 중 비활성 조건과 보조 버튼의 잠금 범위는 기존 동작을 그대로 쓴다.
  • 작성 중인 메시지는 대기 중에도 그대로 남는다(#465).
  • 대화 잠금·한도 소진·연결 미설정 상태의 입력창 표현은 기존 시안의 기준을 유지한다.

접어 둔 행동 묘사는 알약 위 칩으로 보인다. 칩 모서리 shape.chip, 배경 surfaceVariant + outline. 라벨·수정·제거 동작과 "완료가 전송이 아니다"는 규칙은 #213을 그대로 따른다.

유지 기준

  • 행동 묘사 editor 자체의 배치와 300자 counter는 #198·#213 기준이다. 이 시안은 색·모서리만 토큰에 맞춘다.
  • 완료는 pending으로 접을 뿐 전송하지 않는다. 취소는 editor만 닫고 작성 중인 대사를 보존한다.
  • pending 칩이 있어도 전송 버튼의 두 상태 규칙은 같다.

입력 본문만 커진다. 전송 버튼 48과 보조 버튼 줄 13sp는 고정이다. 알약 최소 높이는 본문 높이에 따라 늘어난다.

구현 기준 요약

  • 알약 안에는 입력칸과 전송 버튼만 둔다. 보조 버튼 줄은 알약 위에 유지한다.
  • 전송 버튼은 비어 있음 / 글자 있음 두 상태를 색과 모양으로 구분한다. 대기 중에는 비활성이다.
  • 정지(■) 버튼, 리액션, 읽음 표시는 넣지 않는다.
  • 첨부 가능 종류·전송 조건·글자 수 제한 같은 기능 동작은 바꾸지 않는다.
  • 모든 버튼의 터치 영역은 48dp 이상이다.
