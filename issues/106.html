파괴적 확인

기존 Material AlertDialog 계층을 사용한다. 제목, 영향 범위, 비가역 경고 순서로 읽히며 confirm label은 기능명이 아니라 사용자의 다음 결과를 표현한다.

  • 취소: dialog만 닫고 repository를 호출하지 않는다.
  • 여기서 다시 시작: rollback port에 stable message ID와 role mode를 전달한다.

안전 상태를 짧게 확인시킨 뒤 composer를 다시 활성화한다. Persona Definition과 최신 revision은 rollback 대상이 아니며 그대로 유지된다.

화면 배치와 UI 상태 표현의 기준 문서다. rollback boundary, 원자성, idempotency, write fence와 오류 정책은 앱 Issue #106 및 승인된 PLAN을 따른다. 실제 대화 내용 대신 합성 ID와 역할 라벨만 사용했다.
